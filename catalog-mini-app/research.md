# Исследование: Каталог услуг бьюти-мастера как Telegram Mini App

---

## 5 примеров Telegram Mini Apps в нише бьюти и похожих нишах

---

### 1. Telegram Salon Booking Bot (nazgool97)
**Что делает:** Система записи для салонов красоты. Клиенты бронируют через Mini App, мастера управляют расписанием, владелец получает аналитику — всё внутри Telegram.

**Сильные стороны:**
- Mobile-first дизайн, нативное ощущение Telegram
- Два режима: кнопки в чате + полноценный Mini App
- Self-hosted: все данные остаются у салона
- Автоматические напоминания снижают no-show на ~34%
- Поддержка нескольких мастеров с защитой от двойной записи

**Слабые стороны:**
- Требует разработчика для установки
- Нет встроенной оплаты / депозита
- Нет портфолио и фотогалереи работ
- Аналитика базовая по сравнению с Fresha/Booksy

**Что мы можем сделать лучше:**
- Добавить галерею работ мастера
- Встроить оплату через Telegram Stars
- No-code настройка для не-технических пользователей

---

### 2. AI Beauty Bot (ai-beauty.bot)
**Что делает:** AI-рецепционист для салонов. Отвечает на вопросы, записывает клиентов, синхронизируется с расписанием, отправляет напоминания. 200+ салонов, 150,000+ обработанных диалогов.

**Сильные стороны:**
- Среднее время ответа — 15 секунд
- Понимает естественный язык: "запишите меня" → запускает бронирование
- Работает 24/7 включая ночи и выходные
- Настройка за 5 минут

**Слабые стороны:**
- Зависит от интеграции с Altegio/Fresha
- Нет визуального каталога услуг с фото
- Дорого для мастера-одиночки
- Сложные запросы эскалируются к человеку

**Что мы можем сделать лучше:**
- Добавить визуальный каталог с фото внутри Mini App
- Standalone режим без сторонних интеграций

---

### 3. HeyBookMeBot (telegrambooking.com)
**Что делает:** Универсальный бот для записи. Клиент выбирает время, получает подтверждение, оба участника получают уведомления.

**Сильные стороны:**
- Простая настройка, не нужен разработчик
- Работает для любого типа услуг
- Клиенту не нужно устанавливать ничего лишнего

**Слабые стороны:**
- Кнопочный чат-бот, а не полноценный Mini App — выглядит устаревшим
- Только для одного мастера
- Нет оплаты, нет фотогалереи, слабая кастомизация

**Что мы можем сделать лучше:**
- Полноценный визуальный Mini App с календарём и карточками услуг
- Депозит через Telegram Stars
- Брендирование под стиль мастера

---

### 4. ShopsBuilder (shopsbuilder.app)
**Что делает:** No-code конструктор магазинов в Telegram. Каталог товаров с изображениями, корзина, чекаут, 50+ способов оплаты включая Telegram Stars.

**Сильные стороны:**
- Запуск за минуты без кода
- Богатый каталог с фото, описаниями, вариантами
- Поддержка Telegram Stars и банковских карт
- Есть бесплатный тариф

**Слабые стороны:**
- Только продажа товаров — нет записи на услуги
- Все магазины выглядят одинаково
- Нет CRM и инструментов лояльности

**Что мы можем сделать лучше:**
- Объединить каталог услуг + запись + витрина товаров в одном Mini App
- Кастомизация внешнего вида под бренд мастера
- Карта лояльности с прогресс-баром

---

### 5. Durger King (@durgerkingbot) — официальное демо Telegram
**Что делает:** Эталонный демо Mini App от команды Telegram. Каталог с фото и ценами, корзина, чекаут. Задаёт стандарт UX для подобных приложений.

**Сильные стороны:**
- Лучший UX для потока каталог → карточка → корзина → чекаут
- Нативная интеграция: платёжный экран, BackButton, MainButton
- Мгновенная загрузка

**Слабые стороны:**
- Только демо — нет реальных платежей, нет админки
- Нет концепции записи/бронирования
- Нет фильтрации и поиска
- Визуально устарел (дизайн 2022-2023)

**Что мы можем сделать лучше:**
- Применить этот UX-паттерн к каталогу услуг бьюти-мастера
- Добавить поиск и фильтры
- Современный дизайн с dark mode

## Обязательные UI элементы

### Нативные элементы Telegram
- **MainButton** — CTA-кнопка внизу ("Записаться", "Оплатить", "Подтвердить"). Только нативная.
- **BackButton** — кнопка "назад" через `Telegram.WebApp.BackButton`. Только нативная.
- **BottomNavBar** — 3-4 вкладки (Главная, Каталог, Записи, Профиль).

### Компоненты контента
- **Карточки услуг**: фото + название + цена + длительность. Минимум 44px для tap-области.
- **Категории-чипсы**: горизонтальная прокрутка фильтров.
- **Календарь**: сетка месяца с подсветкой доступных/занятых дней.
- **Сетка слотов**: визуальные ячейки свободно/занято.
- **Skeleton-загрузчики**: никаких белых экранов во время загрузки.
- **Поиск**: закреплён вверху каталога.
- **Прогресс-индикатор**: "Шаг 2 из 4" в многоэтапном флоу.

### Формы
- Имя клиента — предзаполнить из `Telegram.WebApp.initDataUnsafe.user`.
- Телефон — через `requestContact()`, не показывать поле ввода вручную.

## Главные боли пользователей (чего нельзя допускать)

1. **Принудительная регистрация** — главная причина брошенных записей. Telegram решает автоматически.
2. **Скрытые цены** — показывать до клика "Записаться".
3. **Медленная загрузка** — задержка 1 сек = -7% конверсии.
4. **No-show без последствий** — депозит при записи решает проблему.
5. **Нельзя перенести запись самому** — самообслуживание обязательно.
6. **Безликий дизайн** — мастер хочет собственный стиль, не корпоративный шаблон.

## Экспертная оценка

---

### 👁 UX-дизайнер

#### Ошибки новичков

**Архитектура и контент:**
- Все услуги в одном плоском списке без категорий — пользователь листает вечно
- Цена скрыта до экрана подтверждения — убивает доверие
- Нет фото прямо на карточке услуги — пользователи не идут искать галерею отдельно
- Нет длительности на карточке — второй вопрос после цены всегда "сколько времени?"

**Флоу записи:**
- Запрашивают телефон/имя — Telegram уже их знает, это лишний шаг
- Показывают полный календарь когда доступны только 2-3 дня — пустой календарь выглядит сломанным
- После записи непонятно: мастер должен подтвердить? Придёт напоминание?

#### Что обязательно должно быть

**На каждой карточке услуги:**
- Название, цена (точная, не "от X"), длительность, минимум одно фото

**В флоу записи:**
- Выбранная услуга видна на всех шагах — пользователь не должен забывать что выбрал
- Показывать только доступные даты, не весь пустой календарь
- Слоты времени как большие кнопки (минимум 44px), не выпадающий список
- Итого: услуга + дата + время + цена перед финальным подтверждением

**Всегда:**
- Фото мастера в шапке — это личная услуга, не маркетплейс
- Кнопка "написать мастеру" всегда доступна в один тап
- Кнопка "назад" не сбрасывает прогресс

#### Что бесит пользователей (по тяжести)

1. **Календарь не показывает доступность** — нажимает 5 дат пока не найдёт свободную. Главная точка потери пользователей.
2. **Размытые цены** — "от X" воспринимается как ловушка, пользователь уходит
3. **Регистрация** — в Mini App это преступление, авторизация уже есть через Telegram
4. **Тишина после записи** — не ясно: слот занят сразу? мастер должен подтвердить?
5. **Галерея оторвана от услуг** — решение принимается по фото, если надо уходить в другой раздел — большинство не пойдёт

#### Топ-5 UX рекомендаций

1. **Флоу вокруг времени, а не услуги** — сразу показать ближайший свободный слот, потом уточнить услугу. Убирает фрустрацию "выбрал услугу — нет слотов".
2. **Карточка услуги сама продаёт** — фото + описание + длительность + цена + кнопка "Записаться" на одном экране. Каждый лишний переход стоит ~15% пользователей.
3. **Никаких промежуточных "вы уверены?"** — цель 60 секунд. Каждый диалог подтверждения добавляет 10-15 секунд и когнитивную нагрузку.
4. **Личность мастера, не просто услуги** — настоящее фото, 2 строки о себе, опыт. Повышает конверсию первичных клиентов.
5. **Пустые состояния так же важны как основной флоу** — вся неделя занята (показать следующую дату), услуга убрана (редирект), мастер отменил запись (push + ссылка перезаписаться). Это случается каждую неделю.

**Архитектура 60-секундного флоу:**
```
Открытие Mini App (1с)
→ Каталог с фильтром категорий (5с)
→ Карточка услуги с фото + цена + длительность (10с)
→ Нажать "Записаться" → ближайшая дата уже выбрана (5с)
→ Выбор слота времени (10с)
→ Экран подтверждения: услуга / дата / время / цена (10с)
→ "Подтвердить" → экран успеха (5с)
Итого: ~46 секунд
```

### 📈 Маркетолог

#### Что заставит записаться

- **Нет регистрации** — клиент уже в Telegram, запись в 3 тапа
- **Ближайший слот сразу** — "Ближайшее время: завтра 14:00" работает лучше чем просто "Записаться"
- **Личный контакт** — клиент уже знает мастера из Telegram. Приложение должно ощущаться как "записаться к знакомому мастеру", не как корпоративный сервис
- **Реальная нехватка слотов** — "осталось 2 места на этой неделе" — это правда, не манипуляция. Работает.

#### Элементы повышающие конверсию

**Портфолио:**
- Фото до/после — "до" делает мастера человечнее, клиент узнаёт себя
- Короткое видео 5-10 сек с результатом работает в 2-3 раза лучше статичного фото
- Показать рабочее место — чистый стол, аккуратные инструменты. Доверие без слов.

**Карточки услуг:**
- Фото первым, цена видна без скролла, длительность рядом
- Одна кнопка: "Записаться" — не "Подробнее"
- Если есть варианты (длина, дизайн) — простой селектор, не отдельные услуги

**Навигация:**
- Каталог плоский: Категории → Услуга → Запись
- Кнопка "Записаться" видна всегда при просмотре каталога

#### Психологические триггеры

| Триггер | Как применить |
|---|---|
| Социальная идентичность | Текст от первого лица: "Я делаю этот дизайн за 90 минут" |
| Визуализация результата | Фото на реальных руках, разные тона кожи — клиент представляет себя |
| Авторитет без формальности | "Работаю с 2018, обучалась гель-скульптуре в Праге" — тепло и профессионально |
| Потеря vs приобретение | "Осталось 3 слота на неделе" лучше чем "Записывайтесь в любое время" |
| Личный контакт | Настоящее фото мастера — клиент доверяет человеку, не бренду |

#### Как показывать цены

- **Якорение**: начинай с дорогих сложных услуг — после них стандартная цена кажется выгодной
- **Формат**: "2200 ₽ · 75 мин" — цена + время вместе, переосмысляет стоимость
- **Пакеты**: маникюр + педикюр со скидкой, показать зачёркнутую сумму по отдельности
- **Никогда**: "цена по запросу" и непонятные диапазоны без объяснения

#### Социальное доказательство

1. **Фото реальных клиентов** — не сток. Настоящие руки реальных людей.
2. **Скриншоты отзывов из Telegram** — нативно для аудитории, выглядит неотредактированным
3. **Сигнал повторных клиентов** — "80% клиентов возвращаются через 3 недели"
4. **Количество, не только рейтинг** — "187 клиентов в 2025" сильнее чем "4.9 звёзд от 12 человек"

#### Топ-5 маркетинговых рекомендаций

1. **Ссылка везде в Telegram** — bio, закреплённое сообщение, подпись к каждому посту. Аудитория уже тёплая, стоимость активации близка к нулю.
2. **Услуга для первичных клиентов** — отдельная услуга "первый визит" со скидкой. Снижает барьер для новых.
3. **Сообщение после записи = маркетинг** — подтверждение из Telegram включает фото последней работы по выбранной услуге + мягкая просьба поделиться ссылкой.
4. **Посты "закрываю слоты"** — раз в неделю: "На этой неделе осталось 2 вечерних слота — [ссылка]". Самый конвертирующий формат для мастеров в Telegram, без рекламного бюджета.
5. **Оптимизация под повторную запись** — после подтверждения сразу предложить записаться через 3 недели. Ногти требуют регулярного ухода — лови клиента в момент пика энтузиазма.

### ⚙️ Telegram-разработчик

#### Ключевые ограничения

| Ограничение | Что делать |
|---|---|
| `100vh` ломается на iOS при клавиатуре | Использовать `tg.viewportStableHeight` |
| Физическая кнопка "назад" Android закрывает приложение | Перехватывать через `tg.BackButton` |
| Нельзя доверять `initDataUnsafe` на клиенте | Валидировать HMAC-SHA256 на сервере для каждого запроса |
| `localStorage` может быть очищен | Использовать `CloudStorage` API для важных данных |
| Нельзя запустить платёж напрямую из Mini App | Только через `tg.openInvoice(invoiceLink)` от бота |
| Без `requestContact()` телефон не получить | Никаких полей ввода телефона вручную |

#### Что работает отлично — нативные фишки

| Функция | API | Применение |
|---|---|---|
| MainButton | `tg.MainButton` | "Записаться", "Подтвердить", "Оплатить" — липкий CTA |
| BackButton | `tg.BackButton` | Навигация по шагам записи |
| Haptic Feedback | `tg.HapticFeedback` | Тап на слот, успешная запись, ошибка |
| Цвета темы | `tg.themeParams` | Автоматический dark/light mode |
| CloudStorage | `tg.CloudStorage` | Черновики записей, последний просмотр |
| showPopup | `tg.showPopup` | Подтверждение записи — нативно, без кастомных модалок |
| openInvoice | `tg.openInvoice` | Нативная оплата депозита |
| Bot уведомления | `bot.sendMessage` | Push без запроса разрешений — самый надёжный канал |

#### Чего НЕ делать

- **НЕ использовать `100vh`** — ломается на iOS
- **НЕ пропускать валидацию `initData` на сервере** — безопасность
- **НЕ хранить состояние записи только на клиенте** — потеря при разрыве сети
- **НЕ использовать `window.location.href`** для навигации — SPA router с hash/memory history
- **НЕ делать кастомный календарь с нуля** — 2-3 недели работы и баги с таймзонами
- **НЕ полировать из Mini App** — только webhook → bot → пользователь
- **НЕ игнорировать таймзоны** — хранить UTC, показывать в локальном времени клиента

#### Рекомендуемый стек

**Frontend:** React 18 + TypeScript + Vite + TanStack Query + Zustand + Tailwind CSS + `@twa-dev/sdk`

**Backend:** Node.js + Fastify + PostgreSQL + Redis + Grammy (бот)

**Инфраструктура:** Railway/Render (деплой) + Cloudflare R2 (фото) + Stripe/Robokassa (платежи)

#### Топ-5 технических рекомендаций

1. **Блокировка слотов через Redis** — при выборе слота сразу пишем lock с TTL 5 минут. Без этого два клиента могут выбрать одно и то же время одновременно.

2. **4-шаговый визард с сохранением на сервере** — Услуга → Дата/Время → Контакт → Оплата. После каждого шага `PATCH /booking-drafts/:id`. Выживает при закрытии приложения и возобновлении.

3. **Использовать нативные примитивы Telegram максимально** — заменить кастомные модалки на `tg.showPopup()`, лоадеры на `tg.MainButton.showProgress()`. Сокращает код на ~30% и ощущается нативно.

4. **Галерея оптимизирована для мобильного интернета** — хранить оригиналы на S3/R2, генерировать `thumb_400x400.webp` и `full_1200x1200.webp`. Lazy loading, CDN. Первоначальная загрузка галереи до 200KB.

5. **Три бот-уведомления для MVP:**

| Триггер | Кому | Содержание |
|---|---|---|
| Оплата получена | Клиент | Услуга, дата/время, "добавить в календарь" |
| Новая запись | Мастер | Имя клиента, телефон, услуга, время + кнопки [Подтвердить] [Отменить] |
| За 24ч до записи | Клиент | Напоминание + кнопки [Буду] [Отменить] |
